# Менеджер паролей (CLI)

Консольное приложение на Python для хранения паролей. Данные хранятся локально в SQLite3, пароли шифруются с помощью Fernet.

## Особенности

- **Мастер-пароль.** При первом запуске программа просит придумать мастер-пароль. В базе хранится только его хеш SHA-256 с солью, сам пароль нигде не сохраняется. При следующих запусках без мастер-пароля войти нельзя: даётся 3 попытки.
- **Шифрование.** Пароли записей шифруются Fernet (библиотека `cryptography`). Ключ хранится в файле `.key` рядом с программой и создаётся автоматически при первом запуске (права доступа `600`, только для владельца).
- **SQLite3.** Все записи лежат в файле `passwords.db`. При каждом старте программа проверяет таблицы и при необходимости создаёт их.
- **Запись** состоит из названия (откуда, например «Google»), логина и зашифрованного пароля. Названия уникальны, регистр не учитывается: «Google» и «google» считаются одной записью.
- **Генератор паролей.** Пароль длиной от 4 до 128 символов, в нём всегда есть строчные и заглавные буквы, цифры и спецсимволы. Используется криптографически стойкий модуль `secrets`.
- **Копирование в буфер обмена.** Команды `get` и `new` сразу копируют пароль в буфер (подробнее ниже).
- **Ввод скрыт.** Пароли вводятся через `getpass` и не отображаются в терминале.

## Структура проекта

| Файл | Назначение |
|------|------------|
| `main.py` | CLI: вход, обработка команд, буфер обмена |
| `db.py` | Функции для работы с базой SQLite3 |
| `crypto.py` | Хеширование мастер-пароля, шифрование Fernet, генерация паролей |
| `requirements.txt` | Зависимости |

Файлы `passwords.db` и `.key` создаются при первом запуске и добавлены в `.gitignore`.

## Установка

Нужен Python 3.10 или новее.

```bash
cd password_generator
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Использование

```bash
python main.py <команда>
```

| Команда | Что делает |
|---------|------------|
| `add` | Добавить запись: название, логин, пароль. Если оставить пароль пустым, он будет сгенерирован. |
| `get` | Показать логин и пароль по названию и скопировать пароль в буфер обмена. |
| `list` | Показать все записи (названия и логины, без паролей). |
| `delete` | Удалить запись по названию (с подтверждением). |
| `new` | Сгенерировать новый пароль, скопировать его в буфер и при желании сохранить как запись. |

Каждая команда сначала запрашивает мастер-пароль.

Пример:

```text
$ python main.py get
Введите мастер-пароль:
Название: Google
Название: Google
Логин:    me@gmail.com
Пароль:   s3cret!
Пароль скопирован в буфер обмена.
```

## Как копировать пароли

### Автоматически

Команды `get` и `new` сами копируют пароль в буфер обмена. Чтобы вставить его в нужное поле, нажмите `Cmd+V` (macOS) или `Ctrl+V` (Windows/Linux).

Для копирования используются системные утилиты, ставить дополнительные Python-пакеты не нужно:

| ОС | Утилита | Установка |
|----|---------|-----------|
| macOS | `pbcopy` | встроена |
| Windows | `clip` | встроена |
| Linux (Wayland) | `wl-copy` | `sudo apt install wl-clipboard` |
| Linux (X11) | `xclip` или `xsel` | `sudo apt install xclip` |

### Вручную

Если утилиты нет, программа выведет «Буфер обмена недоступен — скопируйте пароль из терминала вручную». В этом случае выделите пароль в строке `Пароль:` мышью (в большинстве терминалов слово выделяется двойным щелчком) и скопируйте:

- macOS (Terminal, iTerm2): `Cmd+C`
- Windows Terminal: `Ctrl+C` или правый щелчок
- Linux (GNOME Terminal и др.): `Ctrl+Shift+C`

> Совет: после вставки очистите буфер обмена или скопируйте что-нибудь другое, чтобы пароль не остался в буфере. Также стоит очистить экран терминала (`clear`), чтобы пароль не остался видимым.

## Безопасность

- **Не теряйте `.key`.** Без него сохранённые пароли не расшифровать. Делайте резервную копию `.key` вместе с `passwords.db`.
- **Храните `.key` отдельно от базы.** Ключ лежит рядом с базой, поэтому тот, у кого есть доступ к обоим файлам, сможет расшифровать пароли без мастер-пароля. Для учебного проекта это допустимо, но для реального использования ключ лучше хранить отдельно.
- **Мастер-пароль нельзя восстановить.** Если вы его забыли, удалите `passwords.db` и начните заново (все записи будут потеряны).
